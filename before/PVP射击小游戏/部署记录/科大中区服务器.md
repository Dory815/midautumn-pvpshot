## 启停和日志

```bash
ssh -p 26622 <ssh用户>@<服务器IP>
cd /home/<ssh用户>/pvpshot-campus-26.2
./manage.sh check
./manage.sh start
./manage.sh status
./manage.sh stop
```

本服务器的 `eula.txt` 已根据用户明确授权设置为 `eula=true`。管理脚本不会自行接受协议，新部署实例需要管理员阅读 https://aka.ms/MinecraftEULA 并确认同意。

`start` 只提交后台启动，是否启动完成要查看 `logs/latest.log` 中的 `Done`，并通过连接检查确认。`stop` 向游戏发送正常停止命令，最多等待 60 秒，超时也不会强制结束进程。

实时日志：`tail -f logs/latest.log`，按 Ctrl+C 退出日志查看不会关服。

交互控制台：`./manage.sh console`。按 Ctrl+B 后再按 D 脱离控制台并保持运行。通过管理脚本执行命令也可以避免进入控制台。

## 比赛管理

```bash
./manage.sh command 'list'
./manage.sh command 'function ustc_pvp:preset/three'
./manage.sh command 'function ustc_pvp:preset/five'
./manage.sh command 'function ustc_pvp:preset/deathmatch'
./manage.sh command 'function ustc_pvp:reset/start'
```

模式切换会开新局，但不会修复地形。恢复命令保留所选模式，恢复建筑、清除玩家搭建并重置比赛；等待顶部进度结束再继续操作。不要删除 `world/dimensions/ustc_pvp/template/`。

所有玩家均可按大厅按钮，或使用 `/trigger pvp_reset`（恢复）、`/trigger pvp_kit`（补齐装备）、`/trigger pvp_lobby`（大厅）、`/trigger ustc.mode set 3`／`set 5`／`set 1`（三点／五点／死斗）。不需要逐个授权或 OP。重置中再次请求不会重启进度，完成后有 15 秒冷却和明确提示。

如需游戏内管理权限，请先使用 LyerSkin 账号成功进入服务器，再在服务器控制台执行 `op 你的角色名`。仅对实际管理员授予权限。

## 备份和恢复

`release/` 留有原始服务端 ZIP、两个正式数据包 ZIP 和发布校验清单，可用于重新部署。游戏进行后的进度需要另外备份：先正常 `stop`，再复制或打包完整 `world/`。恢复玩家进度也需要停服操作。

部署脚本只允许安装到不存在世界的新目录，拒绝覆盖已有 `world/`。后续更新应先备份，不能重复运行首次部署脚本覆盖游戏存档。
