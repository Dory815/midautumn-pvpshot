# 更新日志 · 服务端模组版（pvpshot 1.0.0-m1）

> 面向玩家与管理员的简短说明。完整背景与设计见 `specs/PRD.md`、`specs/SPEC.md`；
> 每次改动的明细见 PRD 的「12. 变更记录」与 git 提交记录。

## 这一版是什么

用 Fabric **纯服务端模组**重写了原数据包玩法的主体部分，玩家**不需要装任何客户端 Mod**，
原版 26.2 客户端直连即可。目前是「模组 + 数据包共存」状态：模组已接管的部分按模组跑，
尚未接管的部分（部署物、补给箱、大厅/队伍/复活、死斗击杀计分）仍由原数据包驱动。
**地图、点位、出生点、保护区、复原范围全部沿用现状，没有改动。**

## 与数据包版的主要区别

| 方面 | 数据包版 | 现在这一版 |
|---|---|---|
| 运行形式 | 796 个 `.mcfunction`，实时逻辑靠"每 tick 全员轮询 + NBT 匹配" | 22 个 Java 类（约 3000 行）+ 保留的数据包；实时逻辑改为事件与对象，不再轮询 |
| 设施保护 | 自研插桩模块改官方 jar 字节码（还硬编码 jar 的 SHA-1，换版本即失效） | 6 个 Mixin 拦截点 + 181 个区域按区块索引查表，O(1) 判定；规则与行为不变 |
| 整场复原 | 176 个批次、2808 条 `clone` 命令一口气执行 | 用原版 `StructureTemplate` 搬运同样的 2808 段，每 tick 限时 5 ms 分帧，复原期间服务器全程可响应 |
| 点位可视化 | 无 | 贴地多层**火焰范围环**、点位**发光标记**（地下隐形史莱姆 + 基岩包裹 + 抗性 V）、定位条 **A~E 航点**、**信标光柱颜色**跟随占领队伍、**定位条字母颜色**跟随占领队伍 |
| 定位条内容 | 默认只有玩家（收发范围是 0） | 抢点模式：点位 A~E + 玩家；团队死斗：**只有玩家** |
| 团队死斗重生 | 有概率落在 A~E 点位上的"固定前线点" | **始终在红/蓝基地的固定重生点** |
| 部署物（炮/炮塔/掩体） | 生存正常；创造模式不扣物品，且失败时净多 1 个 | 创造与生存一致：成功 −1、失败 0；并在服务器日志里记录每次消耗/退还 |
| 武器与载具 | 数据包 + 插桩 Java 两套实现 | 模组内统一实现（弓弩、SMG、霰弹枪、三种重武器、温雷、战斗机、楼顶弹射器、掉落物拦截），数值与《武器平衡表》一致 |
| 顺带修掉的老问题 | — | 点位航点重复创建（曾堆到 1166 个隐形实体）、部署物退还客户端不同步、服务端控制台乱码（`chcp 65001`） |

## 性能

- 空载 / 单人：最近 100 tick 平均 **3.4 ~ 4.8 ms**（本测试服视距 10、模拟距离 8，比线上更高）。
- 整场复原：每 tick 额外开销 **≤ 5 ms**（限时切片），不再是"一次性几千条命令"。
- 数据包的性能瓶颈（每 tick 全员扫描、单个函数 137.9 KB、NBT 匹配筛实体、命令堆出来的地形复原）
  在模组侧已被替换；**尚未接管**的部分继续沿用数据包。

## 管理员新增：逐 tick 性能采样

`/pvpshot tickrecord <tick 数>` 会把之后每个 tick 的 MSPT 单独写进服务器日志（前缀 `[tickrec]`），
配合 `tools/stress/` 里的 `extract-mspt.py`（日志 → CSV）和 `plot-mspt.ps1`（CSV → 曲线图，
自动标出最大/最小极值点）就能出压测曲线。首轮"1300 发投掷物齐射"的曲线与报告见 `docs/压测/`。

日志默认**安静**：每 100 tick 的 MSPT 摘要、点位归属变化、信标换色、部署物消耗/退还这些高频播报
默认不输出（终端与日志都清爽）；需要压测或排查时 `/pvpshot log on` 打开，`/pvpshot log off` 关掉。
`/pvpshot tickrecord` 不受此开关影响。

## 已知环境问题（开服者请注意）

**JDK 25.0.2 的 G1 垃圾回收器存在内部崩溃 bug**：测试服曾出现
`Internal Error (g1HeapRegionManager.cpp:55) ... master free list MT safety protocol at a safepoint`，
进程直接退出、日志里没有异常栈（细节见 `docs/崩溃记录-2026-09-25-G1内部错误.md`）。
这不是模组或数据包的问题，但会影响开服。处理办法二选一：

1. 用更新的 JDK 补丁版本（线上是 OpenJDK 25.0.4.1，本测试服已从 25.0.2 切走）；
2. 或者像本测试服一样把启动参数换成 ZGC：`-XX:+UseZGC`
   （本仓库 `server/start.bat` 已改好，并加了 `-XX:ErrorFile=logs\hs_err_pid%p.log`）。

**ECO（EntityCollisionOptimizer）在超大半径实体查询上会把主线程卡死**：2026-09-25 两次实测，
只要执行类似 `execute if entity @e[...,distance=..1000000]` 这种"半径极大"的选择器，
服务端主线程就会停在 `EntitySectionStorage.handler$…$entity_collision_optimizer$eco$nativeGetEntities`
里面出不来（CPU 单核跑满、spark 持续报 `Timed out waiting for world statistics`），
只能重启进程恢复。普通玩法里的选择器半径都很小（`distance=..2` / `..5` / `..24`），
所以不影响正常对局；**但排查问题时不要用大半径 `@e` 选择器**，
要查实体请用 `x/y/z` 加小半径（例如 `@e[type=text_display,x=…,y=…,z=…,distance=..2]`）。
另外那次卡死也让服务端重启了两次（当时都是 0 人在线，未影响玩家）。

## 玩法改动（2026-09-25）

| 项目 | 现在 |
|---|---|
| 手雷 | **按下右键点火 · 引信 3 秒 · 松开右键扔出**（按住不放就在手里炸）；点火瞬间与剩余引信会显示在屏幕中央偏下的提示条上。爆炸**对实体伤害减半**（实测同距离同参数：普通 TNT 45.1 点 → 手雷 23.6 点；地形破坏与击退不变） |
| 弩 | 不再"每人限 1 把"：**每持有一把已装填的弩，叠加 3 级缓慢**（每 20 tick 检查一次） |
| 破拆火箭 | 补给量**已退回原值**：普通箱 4 发、体育馆富箱 2 发、南北高级箱 2 发（当天先按"刷新太少"×1.5，随后按反馈退回） |
| 鸡蛋冲锋枪 | 近距离伤害 4 → **2 HP**（远端不变 1 HP），近距 DPS 26.7 → 13.3；弹药 48、射速 6.7 发/秒、近距窗口 9 tick 都不变 |
| 点位附近的树 | A~E 每个点位**半径 40 格内的树全部清掉**（原树挡住点位视野，也挡住 A/C 点楼顶弹射通道）；主世界与复原模板同步清理。清两遍：先清树叶与木质方块，再清"长在树上"的栏杆与墙块（云杉栏杆 / 泥砖墙 / 橡木栏杆 / 海晶石墙，共约 2400 块）；去皮木搭的宣传栏、建筑的铁栏杆与施工脚手架等一律保留 |
| 点位信标 | **E 点信标恢复发光**：它的 3×3 铁块底座被"航点基岩外壳"盖成了基岩，信标没有金字塔就不发光（方块实体 `Levels` = 0）。已把底座重建为铁块，`Levels` 回到 1，光柱恢复并按占领队伍颜色着色 |
| 基地出生点 | 红、蓝两队基地的 **`base_menu` 命令方块已彻底删除**（含按钮、底座与"补给 / 返回大厅"浮空文字）。以前"删了又回来"是因为每局复位的收尾会调用设施重建脚本 `ustc_pvp:build`，现在改成**主动清空**，复位、重建、复原模板三条路径都不会再出现；补装备仍可用 `/trigger pvp_kit` |
| 场地复原 | 默认"每 tick 搬 4 片（=1 个柱段，切成 4 片）"，整场约 140 秒；可用 `/pvpshot restore speed <片/tick> [间隔 tick]` 调慢（例如 `speed 2 2` 约 280 秒、峰值更低） |
| 战斗视觉 | **伤害数字**（受击时头顶弹出，白/黄/红按伤害分档）、**头顶血条**（10 格进度条 + 血量数字，只在变化时更新）、**尸体**（死亡处生成带皮肤的"人偶"，保留随身装备，20 秒后消失）。全部用原版实体实现，**原版客户端也能看到**；不需要时用 `/pvpshot visual off` 关掉 |

> 客户端可选性：服务端装的模组要么是纯服务端逻辑，要么只是"多发一点可选数据"；
> **未装任何模组的原版客户端可以正常进服**，一样能看到上面这三项视觉（走原版实体渲染），
> 资源包也仍然是可选的。
>
> 客户端模组按 `environment` 分两类：`env=*` 的（Fabric API、Carpet、spark、FerriteCore、
> AppleSkin、Xaero 地图、碰撞优化）才需要服务端也装；纯 `env=client` 的
> （钠、Iris、ImmediatelyFast、ModMenu、IMBlocker、MouseTweaks、Voxy、聊天头像、更多聊天记录）
> 只放客户端，服务端装了也会被 Fabric 跳过。

> 复原期间平均 MSPT 约 24 ms；打开新一批区块的那一两个 tick 会短暂到 50~95 ms
> （区块加载 + 光照 + 方块实体，和搬运方块数量无关）。测试服的看门狗已关闭
> （`max-tick-time=-1`），不会因为复原被强制关机；正式服若开着看门狗，请同样关掉或调大。

## 开服方式（2026-09-25 起）

- **地址**：`<服务器IP>:25566`（校园网内可直接连；换网后 IP 可能变，用 `ipconfig` 核对）。
- **登录方式：LyerSkin 外置登录**。先在 <https://auth.lylighte.cc/> 注册并创建角色，
  然后在启动器（HMCL / PCL）里添加外置登录地址 `https://auth.lylighte.cc/skinapi`，
  登录并选中角色后启动 **Minecraft 26.2** 进服；离线昵称进不来。
- **玩家端不需要装任何模组**（模组全在服务端）。服务器资源包会自动下发（很小的定位条字母图标），
  不装也能正常玩。
- **部署只需要一个文件**：`mods/pvpshot-1.0.0-m1.jar` —— Fabric API、Carpet、spark、
  实体碰撞优化都已嵌套在里面。

## 客户端整合包

`dist\中秋校园枪战小游戏-客户端整合包.zip`（75.5 MB，解压后 89.6 MB）：解压到
`…\.minecraft\versions\中秋校园枪战小游戏\`，或在启动器里"导入整合包"选中这个 zip 即可。

包里带了：客户端模组、**各模组配置**、光影与资源包、**多人游戏列表**（已含 `<服务器IP>:25566`）、
**Xaero 小地图 / 世界地图数据**、**Voxy 远景数据**，以及一份安装说明（含 LyerSkin 外置登录步骤）。

重新打包（客户端有改动时跑一下）：

```powershell

```
