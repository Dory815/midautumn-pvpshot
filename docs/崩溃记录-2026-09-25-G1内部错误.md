# 崩溃记录 · 2026-09-25 02:09（JVM 内部错误，G1 GC）

## 现象

测试服在运行 7 分钟后突然整体消失：`latest.log` 最后一行是正常的 tick 采样（02:09:00），
没有任何异常栈；进程退出，端口 25566 不再监听。

## 原因（JVM 自身的问题，不是模组 / 数据包）

服务器根目录留下了 `hs_err_pid9792.log`（已归档到 `logs/hs_err_pid9792.log`），头部是：

```
#  A fatal error has been detected by the Java Runtime Environment:
#  Internal Error (g1HeapRegionManager.cpp:55), pid=9792, tid=46756
#  guarantee(Thread::current()->is_VM_thread() || FreeList_lock->owned_by_self()) failed:
#     master free list MT safety protocol at a safepoint
# JRE: OpenJDK Runtime Environment Microsoft-13053607 (25.0.2+10) (build 25.0.2+10-LTS)
# Current thread: WatcherThread "VM Periodic Task Thread"
# Native frames: 全部是 jvm.dll 的地址（无任何模组/原版方法的帧）
```

- 崩溃点是 **G1 垃圾回收器的区域管理器**（`g1HeapRegionManager.cpp`）里的一条内部断言，
  发生在 GC 线程（`WatcherThread` / "VM Periodic Task Thread"）上；
- 栈里只有 `jvm.dll` 的帧，模组类名只在文件的 "JIT 编译事件" 列表里出现过（正常现象），
  所以**不是**本模组或数据包逻辑导致的崩溃；
- 崩溃时的堆状况：`garbage-first heap`，region 2M，已提交 1.1G、已用约 0.48G，
  说明不是内存耗尽（`-Xmx3G` 远没到），而是 GC 内部竞态被触发。

## 处理

1. `server/start.bat` 的 GC 从 G1 换成 **ZGC**（并保留原来的堆与编码参数）：

```
"%JAVA_HOME%\bin\java.exe" -Xms1G -Xmx3G ^
  -XX:+UseZGC ^
  -XX:ErrorFile=logs\hs_err_pid%%p.log ^
  ...
```

2. 用 `jcmd <pid> VM.flags` 复核，确认新进程确实跑在 ZGC 上：
   `-XX:+UseZGC -XX:ZOldGCThreads=8 -XX:ZYoungGCThreads=8`；
3. 以后 JVM 崩溃文件统一写到 `logs/hs_err_pid<PID>.log`，不会再散落在服务器根目录；
4. 服务器已用新参数重启并恢复正常（tick 采样 4~7 ms）。

## 给线上服的提醒

- 线上用的是 OpenJDK **25.0.4.1**（本测试服是 Microsoft 25.0.2+10），补丁版本更新，
  可能已经修掉这个竞态；建议先确认线上 JDK 是否 ≥ 25.0.4；
- 如果没有把握，按同样方式换成 ZGC（或等 JDK 再打补丁）即可绕开这条代码路径；
- 建议线上也加上 `-XX:ErrorFile=logs/hs_err_pid%p.log`，下次万一再崩能直接拿到现场。
